# WePlay perf24 — iAP2 控制队列断线修复测试版

基于已安装的 perf23（图标 5、名称 WePlay、声音正常的旧版分支）。

## 修复范围

2026-10-13 19:45 后的七次自动断线均出现 `iAP2 received-control queue limit exceeded`，随后才关闭 Wi-Fi Direct。20:26 的手动退出不计入故障。

- 控制接收队列仍限制为 64 个片段 / 1 MiB。达到容量后，保留下一片段，暂缓读取新数据，等待消费恢复；不再因短暂积压立即拆掉 CarPlay。
- 等待期间继续处理发送队列、协议计时器和关闭请求。持续 15 秒没有接收消费进展才报告明确的卡住错误；协议自身的断开或超时仍正常处理。
- AirPlay 输入桥也使用有界等待，把暂停传递到独立网络接收线程，避免下游恢复之前上游缓冲先溢出。输入桥限制 1 MiB，CSM 原始缓冲小于 128 KiB，不靠无限堆积数据掩盖故障。
- 每次向链路解析器喂入至多 1 KiB，再及时排空事件，避免一个 TCP 批次触发下一层事件队列溢出。
- CSM 按需解出一帧，避免一个合法大批次挤爆原先 64 帧的中间队列。
- 默认在格式化之前关闭逐帧 TLV / 十六进制转储。保留连接状态、错误和限频的队列积压/恢复摘要。

本次未修改音频输出、麦克风、300 毫秒音频缓冲、仪表布局、分辨率、帧率和 Wi-Fi 信道设置。包名及签名与原版一致，可覆盖安装并保留设置。

## 实车验证

先按平时的方式使用 Wi-Fi Direct，连续导航并听歌 60–90 分钟，观察是否自动退回等待页面，以及声音、Siri 和仪表地图是否正常。如果再次断开，记录大致时间，保留日志。

该补丁针对已确认的控制队列溢出路径。实车稳定性仍需长时间验证；不能承诺解决射频干扰、车机驱动或手机侧主动断开等其他原因。
