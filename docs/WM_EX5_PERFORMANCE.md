# 威马 EX5 低延迟与固定无线信道测试版

## perf6 联网设置修复

当前威马包为 `0.2.17-legacy.1-wm-ex5-perf6`，versionCode 44。保留 perf5 的音频、低延迟、蓝牙自动开启、USB 防闪退与仪表适配。

同一局域网设置会读取当前已连接的 Wi-Fi 名称，并提供“读取当前 Wi-Fi 名称”按钮。名称与此前保存的网络不同时，清空旧密码输入框，避免把其他网络的密码保存到当前网络；必须填写当前路由器密码并保存。无法读取名称时仍可手动填写，保留 SSID 的空格。此修复针对实车报告中的 `PDCN_5G` / `PCDN_5G` 名称错误，连接层仍校验实际网络，修改在下次连接生效。

Wi-Fi Direct 默认固定 5GHz 36 信道，另可选 44、157，以及 2.4GHz 1、6。系统拒绝所选信道或读到不同实际频率时，停止连接并报告原因；驱动不提供实际频率时仍记录未验证。同一局域网模式跟随外部路由器信道。

首次升级把制造商设置为“威马”，之后的手动修改保留。主屏默认 40% / 8 fps，仪表默认 40% / 4 fps、保持显示区域大小并等比例居中。已在 perf5 手动修改的画面、连接、音频和仪表参数保留。

本轮按用户要求未连接 ADB、未安装或进行新的实车测试。下文保留早期版本的适配记录。

验证：项目规定的 CI 命令通过，共 2042 项单元测试（shared 1097、common 941、home 4），无失败或跳过。三个应用的 lint 无错误，保留原有 22 / 5 / 2 项警告。新增 API 23 测试覆盖当前 SSID 读取与密码清空、手动输入回退和三个新增信道的实际频率校验；升级测试覆盖一次性制造商迁移和保留自选参数。首轮新增测试缺少资源引用，修正后完整复测通过；原 USB 100ms 等待用例首轮超时，未修改实现或测试，完整复测通过。

## 默认行为

仅 `com.shihab.diplay.wmex5` 测试包默认启用低延迟模式。使用 SurfaceView 显示主屏硬件解码结果，视频平滑延时为 0，不启用原先 30 fps 下约 140 ms 的平滑等待。主屏收到的视频在解码队列中超过 150 ms 时触发关键帧恢复；已解码但过时的画面可以跳过显示，不破坏编码帧的参考链。第一幅图及至少每 500 ms 的过时画面刷新仍保留，以免较慢的解码器长期没有可见输出。

触控发送队列只合并同一会话中相邻、尚未发送的 MOVE，保留 DOWN、UP、CANCEL 和多指增减等事件及其顺序。会话更换后不发送旧会话的触控。视频队列改用受锁保护的帧数与字节计数，减少每次入队时遍历的开销。

仪表地图沿用之前的适配与解码方式。H.264、帧率、分辨率和仪表设置沿用已保存的用户选择。

## 无线连接

威马测试包固定使用 Wi-Fi Direct，并固定请求 5 GHz 的 36 信道（5180 MHz）。Android 6.0 在创建 group owner 前，通过旧版系统信道接口设置工作信道。系统拒绝、调用失败或无回调时停止连接，不改用自动信道或其他热点后端。能读取到实际频率时检查是否为 5180 MHz；实际频率不同则停止连接。

Wi-Fi Direct 的发现监听信道仍按系统接口要求使用 2.4 GHz 的 6 信道，这与承载 CarPlay 的工作信道 36 不同。

部分威马驱动无法回报实际频率。此时报告分别记录请求与实际结果：`requested=36 actualMHz=unavailable verified=false`，热点配置仍请求并向手机通告信道 36，但不能据此宣称已经实测无线工作频率。`actualMHz=5180 verified=true` 才是读取到相符频率。

关闭连接时尝试清除本应用提交的信道限制；检测到另一个应用的热点后保留其组与信道，不修改其他应用的状态。USB 不依赖无线信道要求。

## 实车对比

覆盖安装后确认版本后缀为 `perf1-ch36`。先保持 H.264、30 fps、50% 分辨率（照片中最近一次协商为 540×960），断开后重新连接。检查拖动地图、切换应用、点击按钮的反应，然后开启仪表地图做第二轮比较。

“设置 → 高级”中的“威马 EX5 低延迟（实验性）”可关闭视频与触控优化，改动在下次连接生效。关闭后恢复原显示路径及 250 ms 队列预算，但无线仍固定要求 36 信道。此前保存的视频平滑开关也会恢复；对比时应保持视频平滑关闭。

测试 3～5 分钟后保存完整诊断报告。新增 `queueWaitMax`、`queueFrames`、`queueBytes`、`oldestQueued`、`staleOutputDropped`、`touchQueueAvg`、`touchQueueMax`、`coalescedMoves`，配合已有 rx/shown fps、maxGap、decode p50/p90 区分网络、解码与发送排队。`touch2frame` 是发送触控到下一帧到达的近似统计，不能当作完整点击到画面更新的实测延迟。

如果无线仍慢，同样设置下比较 USB。电脑构建、模拟无线接口测试及 Android 6.0 模拟器检查不能代替实车的无线频率、双屏画面与响应速度验证。
